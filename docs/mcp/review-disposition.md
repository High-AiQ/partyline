# MCP shipping review disposition

This table records the shipping review findings and their disposition for the replacement
MCP history. Test names refer to the repository's capped, temporary-database test suite.
The retained whoami `.txt` files are prose summaries; the hook probes are not evidence of
service-managed provisioning. No live credentials were copied for this review.

| Finding | Disposition and evidence |
| --- | --- |
| Helper `python -m` imports a stale or shadow `partyline` from the caller's working directory (B1). | **Fixed.** The generated entry uses `python -P -m partyline.mcp` and the service root in `PYTHONPATH`. `tests.test_mcp_attach.McpConfigFileTests.test_generated_helper_loads_service_package_from_any_cwd` runs the generated helper from stale-checkout, non-project, and shadow-package working directories and checks the service version. |
| Conventional commit CI rejects commit bodies/trailers in the unpublished MCP range (B2). | **Fixed in history.** The replacement range is rebuilt as one-line Conventional Commits without co-author trailers. The final handoff records the repository's full-range conventional-commit check and version-policy result for the exact replacement tip. |
| Human keyed posts remembered the retry key after delivery, allowing a retry to duplicate a durable post. | **Fixed.** The key is recorded before broadcast and mention routing. `tests.test_idempotent_posts.IdempotentPostsTest.test_human_key_is_saved_before_delivery_can_fail` injects delivery failure, retries the same key, and asserts one durable message. |
| Codex's attachment `config.toml` symlink could persist MCP approval state into the user's global config; conflicting user settings need explicit precedence. | **Fixed.** The user's config is copied into each attachment's `CODEX_HOME`; a stale config symlink is replaced with a private copy. This is a snapshot on first seed: later edits to the global config do not reach an existing home, and trust or approval decisions stay in that attachment's copy. User `command`, `args`, and `env` keys win per key from either config file or inline argv. User `enabled = false` suppresses local injection; user `url` leaves the remote entry untouched. `tests.test_codex_adapter.CodexHomeTest.test_old_config_symlink_becomes_private_on_resume_and_non_bypass_write_stays_local` simulates an approval write without bypass and confirms the source config does not change. `tests.test_mcp_attach.CodexMergeTests.test_user_disabled_or_url_server_is_left_untouched` and `test_partial_user_config_and_argv_values_keep_precedence` cover the conflicts. |
| Prior command-only test runs may have seeded the real Codex home for the synthetic attachment ID `a1`. | **Metadata-only audit; provenance unknown.** The `a1` directory exists with mode `0775` and timestamps 2026-10-17T12:44:58Z; `config.toml` is a regular `0600` file, size 993, mtime 2026-10-14T11:46:06Z and ctime 2026-10-17T12:56:16Z; `auth.json` is a symlink to the user's existing auth file with link timestamps 2026-10-17T12:44:58Z. These times are consistent with prior test activity, but do not establish that the tests created or changed these artifacts. The directory's creator and its prior state are unproven. No contents were read; the artifact was left untouched. |
| MCP helper revocation could be cleared by a later failed call. | **Fixed.** `_revoked` stays set after the initial 401. `tests.test_mcp.RenderAndServerTests.test_revoked_credential_produces_short_error_without_disclosing_token` follows it with another `tools/list`, which receives the helper's non-401 `attachment credential is no longer valid` error; the test also asserts the API capability call was not retried. |
| Deeply nested JSON could raise `RecursionError` and terminate the helper. | **Fixed.** `tests.test_mcp.RenderAndServerTests.test_run_returns_structured_error_for_deeply_nested_json` sends 15,000 nested arrays and checks for a structured parse error. |
| Same-service media URLs embedded in message text could retain loopback or service-host URLs. | **Fixed.** `tests.test_mcp.RenderAndServerTests.test_render_relativizes_media_links_and_caps_output` checks both a media field and a media URL embedded in prose are rendered as `/api/media/...` paths. |
| MCP `upload_file` could post a free-prose caption on the caller's own line. | **Fixed.** `tests.test_mcp.CoreToolTests.test_guide_messages_reactions_and_media_use_fixed_routes` verifies a local file upload still works and a non-empty own-line caption is rejected before upload. |
| `reports` needed a live captain fallback after promotion, without duplicate names, and live scope/schema validation including demotion and revocation. | **Fixed.** `tests.test_mcp_captain.CaptainToolTests.test_reports_use_lead_dispatcher_with_live_scope_and_schema` checks one `reports` name, list/post calls, scope, and the 2,000-character schema limit. `test_reports_fallback_is_denied_after_demotion_and_revocation` checks a demoted caller and a revoked credential. |
| MCP advertised report text up to 12,000 characters, while route `ReportIn` caps it at 2,000. | **Fixed.** The core and captain schemas and handlers use 2,000 characters; coverage is in `test_reports_use_lead_dispatcher_with_live_scope_and_schema` and `tests.test_mcp.CoreToolTests.test_goal_and_report_operations_are_live_gated`. |
| Reaction POST was described as an unconditional add although it toggles. | **Fixed.** Schema, description, and inventory call POST a toggle and DELETE removal. `tests.test_mcp.CoreToolTests.test_guide_messages_reactions_and_media_use_fixed_routes` checks POST and DELETE methods and the advertised toggle description. |
| Inventory had stale route line numbers and incorrect route-to-tool mappings. | **Fixed in documentation.** Set 1 lists handler names plus current registration lines, including the file/image/media and terminal routes. The route check counted 136 Set 1 entries and 104 Set 2 entries and matched all HTTP handlers to registrations; the terminal WebSocket row was verified against `terminal_endpoint` registration. `whoami` maps only to the conversation detail and child-list handlers it calls; capability preflight is described separately and the lead route is no longer attributed to `whoami`. |
| Whoami `.txt` artifacts were presented as raw service-managed proof; probe scripts call adapter hooks, not provisioning. | **Fixed in documentation.** `README.md` and `compat-matrix.md` label the `.txt` files as prose summaries and the launchers as hook-level probes. The generated provisioning/helper subprocess regression is separate test evidence, not a retroactive claim about those artifacts. |
| Additional sanitized runtime evidence. | **No new live-CLI artifact retained.** Existing fixture logs are sanitized protocol observations. No real credential or runtime home was copied to create evidence. The subprocess regression proves helper import selection without a vendor CLI or live database. |
| Message row and retry-key row use separate commits. | **Documented limitation.** A process crash after durable message insertion but before key recording can leave a post that a retry duplicates. This patch makes delivery failure after key recording replay-safe; it does not claim transaction-level crash safety. |
| Idempotency claim locks are in-process. | **Documented limitation.** Correct coordination assumes one Partyline service runtime using the database. Independent service processes sharing that database are not coordinated by these locks. |
| Codex per-attachment home mode, cleanup, and auth behavior. | **Documented limitation.** The review observed attachment homes with mode `0775`, no cleanup (about 217 directories at review time), a symlinked `auth.json` on Linux, and a copied `auth.json` on Windows. This patch does not claim those home lifecycle or platform differences are resolved. Probes did not copy real credentials. |
| Removed 516 MB Codex home provenance. | **Unknown.** A 516 MB home appeared under `docs/mcp/isolate` and was emptied before audit. Its creator and whether it contained auth material are unknown; the empty `isolate/` location remains empty and the provenance is unresolved. |
| Codex user `enabled = false`, `url`, and partial argv overrides. | **Fixed and documented.** User config is copied into the attachment home; supplied `command`, `args`, and `env` keys are retained per key, `enabled = false` suppresses local injection, and a user `url` leaves the remote entry untouched. The test names and non-bypass approval-write regression are listed above. Do not claim that global user config always wins. |
| Non-blocking API scope: message/key atomicity beyond the process-crash window and distributed locking. | **Same documented limitations above.** No exactly-once or multi-process guarantee is claimed. |
